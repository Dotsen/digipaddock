# Worker results

Read this when a comment `[worker] job <id> …` signed `[dev]` appears on your card, or a worker patch is waiting in your card's temp folder.

The coordinator may run a short worker session for a card of yours (a job in a prepared slot under your user, one specialization). It ends with a comment on the card signed `[dev]` — `[worker] job <id> …` with the outcome — and, when it changed code, a patch in that card's temp folder, `/srv/digipaddock-agents/dev/work/tmp/cards/KD-<n>/worker-<id>.patch` (`git diff --binary` against the base it started from; a patch of before KD-9046 stays at `work/tmp/worker-<id>.patch`). Treat it as a colleague's draft, not as finished work: read the comment and the patch, apply it on the card's branch in its worktree (`git apply --3way --index /srv/digipaddock-agents/dev/work/tmp/cards/KD-<n>/worker-<id>.patch`), run the patch's affected checks and consumers, review it as your own code and fix what is wrong, then continue with Workflow 5–6 (the PR and its council). A patch that does not apply or whose tests fail is yours to rework; note the outcome in the card (`--append-notes`). Never open a PR from a worker patch you have not applied and run yourself.
